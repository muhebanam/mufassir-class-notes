# প্রম্পট: প্রতি সূরার জন্য সমৃদ্ধকরণ (শানে নুযূল + হাদীস তাখরীজ + কুরআনিক নাযম)

> এটি সূরা ২৫ (আল-ফুরকান)-এর প্রমাণিত পাইপলাইনের সাধারণীকৃত, পুনর্ব্যবহারযোগ্য প্রম্পট।
> Kilo command হিসেবে ব্যবহার করতে `.kilo/command/surah-enrich.md`-এ রাখা আছে (স্থানীয়, gitignore-এ)।
> ব্যবহার: “সূরা <নাম/নম্বর> এ কাজ করো” — `<NNN>`-এ সূরা নম্বর বসাও।

তুমি একজন দক্ষ ইসলামি গবেষণা-সফটওয়্যার ইঞ্জিনিয়ার। **নির্দিষ্ট সূরাকে** (যে সূরার আয়াত/রুকু ইউজার দেবেন) সূরা ২৫ (আল-ফুরকান)-এর প্রমাণিত পাইপলাইন অনুসরণে সমৃদ্ধ করবে। **কোনো অনুমাননির্ভর তথ্য লেখা যাবে না** (নীতি ৩)।

## ০. ইনপুট ও প্রাথমিক যাচাই
- ইউজারের দেওয়া **সূরা নম্বর ও নাম**, **রুকু সংখ্যা**, **আয়াত পরিসর** নিশ্চিত করো।
- `<সূরা_নাম>/` ফোল্ডারে ৬/৭টি রুকু MD (১৬-অধ্যায় কাঠামো) ও `_sources/ruku_XX_raw.json` আছে কি না দেখো।
- `scripts/build_web_data.py`-এর `parse_section_ayah_subsections` (প্রতি-আয়াত ডেলিমিটার `### আয়াত N:` / `### আয়াত X–Y` গ্রহণ করে) ও `munasabat` পাস-থ্রু (লাইন ~৯১৪) যাচাই করো।
- `web/src/components/MunasabatSection.jsx` ও `web/src/utils/tafsirTakhrijAdapter.js` ইতিমধ্যে সম্পন্ন কি না দেখো (না থাকলে সূরা ২৫-এর ফাইল থেকে কপি করো)।

## ১. অনুমোদিত সিদ্ধান্ত (ইউজার কর্তৃক পূর-অনুমোদিত — পুনরায় জিজ্ঞাসা নয়)
1. **তাখরীজ কাঠামো:** প্রতি রুকুর `## ৬.` অধ্যায় সব শানে নুযূল/হাদীস/আসার `tafsirTakhrijAdapter.js`-সামঞ্জস্য **প্রতি-আয়াত ফরম্যাটে** রূপান্তর — যাতে “কার্ড ভিউ” + “তাখরীজ সারণি” টগল ও `সহীহ/হাসান/যঈফ` ব্যাজ সক্রিয় হয়।
2. **নাযম UI:** `munasabat.nazm_scholars` ঐচ্ছিক ফিল্ড + `MunasabatSection.jsx`-এ collapsible “শাস্ত্রীয় নাযমুল কুরআন” প্যানেল (RTL আরবি + খণ্ড-পৃষ্ঠা ব্যাজ + বাংলা বিশ্লেষণ)। ফিল্ড অনুপস্থিত সূরায় UI অপরিবর্তিত।
3. **Zero-Hallucination নীতি:** স্বতন্ত্র শানে নুযূল না থাকলে স্পষ্ট লেখো *“স্বতন্ত্র শানে নুযূল বর্ণিত হয়নি”*; কেবল যাচাইকৃত মা'সূর আসার ও সহীহ হাদীসের তাখরীজ — কোনো গল্প আরোপ নয়।

## ২. MCP উৎস ম্যাপ
- **শানে নুযূল/তাখরীজ:** `tafsir-center` `fetch_nuzool_reason(surah, ayah, sources=['nuzool','wahidi_asbab'])` + `fetch_tafsir(sources=['mathur','tabary','katheer','qurtubi'])`; `shamela-qg` — ওয়াহিদী (আসবাবুন নুযূল), সুয়ূতী (লুবাবুন নুকূল), ওয়াদিঈ (আস-সহীহুল মুসনাদ); `shamela_lookup_hadith` + `shamela_lookup_rijal` দিয়ে খণ্ড/পৃষ্ঠা/নং ও হুকুম।
- **নাযম/মুনাসাবাত:** *নাযমুদ দুরার* (বিক্বাঈ, turath book 9098) — সূরার `title_id`/পৃষ্ঠা পরিসর **TOC ব্রাউজ করে নির্ণয়** (অনুমান নয়); *মাফাতিহুল গাইব* (রাযী, slug `razi`), *আত-তাহরীর ওয়াত-তানবীর* (ইবনে আশূর, slug `ibn_ashur`)।
- **শর্ত:** যেকোনো আরবি উদ্ধৃতি/খণ্ড-পৃষ্ঠা/শামেলা আইডি MCP-তে প্রকৃত পাওয়া না গেলে স্থায়ী ডেটায় যাবে না।
- **অফলাইন হলে:** `files.turath.io/books-v3/<id>.json` সরাসরি ডাউনলোড; `quran.ksu.edu.sa` ক্রস-রেফারেন্স। হারভেস্টেড ডেটা `_work/s<NNN>/`-এ সেভ করো (gitignore-এ)।

## ৩. ডেটা স্কিমা
### ৩.১ raw আর্কাইভ `_sources/`
- `surah<NNN>_asbab_nuzul_raw.json` — প্রতি আয়াত: `{ayah, has_direct_nuzul, sirah_context_only, nuzul_reports:[{source, arabic_text, editorial_note}], related_hadiths:[]}`।
- `surah<NNN>_nazm_raw.json` — বিক্বাঈ/রাযী/ইবনে আশূরের আরবি উদ্ধৃতি + মুদ্রিত খণ্ড-পৃষ্ঠা + shamela id।

### ৩.২ রুকু enrichments `_sources/ruku_XX_enrichments.json`
```json
{"surah_id": N, "ruku_id": R, "ayahs": [
  {"ayah": A, "munasabat": {
    "prev_ayah_link": "...", "current_ayah_focus": "...", "next_ayah_link": "...",
    "source": "নযমুদ দুরার (বিক্বাঈ), মাফাতিহুল গাইব (রাযী), আত-তাহরীর (ইবনে আশূর)",
    "nazm_scholars": [
      {"scholar": "...", "book": "...", "citation": "খণ্ড X, পৃ. Y (shamela id=...)",
       "arabic_excerpt": "হুবহু আরবি", "analysis_bn": "বাংলা বিশ্লেষণ"}
    ]}}]}
```
- **প্রতি আয়াতে** `prev/current/next/source` + `nazm_scholars ≥ ২` (বিক্বাঈ + রাযী/ইবনে আশূর) বাধ্যতামূলক; শেষ আয়াতের `next_ayah_link` পরবর্তী সূরার সূচনার সঙ্গে যুক্ত হবে।
- আরবি উদ্ধৃতি **হারভেস্টেড ফাইল থেকে** যোগ করো; বাংলা বিশ্লেষণ লেখক-কৃত। বড় ডেটা ২ ভাগে লেখো (write size limit এড়াতে)।

### ৩.৩ রুকু MD `## ৬.` টার্গেট ফরম্যাট
```markdown
## ৬. শানে নুযূল, সংশ্লিষ্ট ঘটনা ও হাদীসের তাখরীজ
> নীতি ৩ নোট...

### আয়াত N: [শিরোনাম]
> «যাচাইকৃত আরবি মতন»
- **তাখরীজ:** সংকলন, কিতাব, হাদীস নং ...
- **মুহাদ্দিসদের হুকুম:** সহীহ/হাসান/যঈফ — সনদ-বিশ্লেষণসহ
- **উৎস:** `[src:shm-...]`

### আয়াত X–Y: [শিরোনাম]   (যৌথ নুযূল হলে রেঞ্জ হেডিং)
...
### আয়াত N: [শিরোনাম]
**স্বতন্ত্র শানে নুযূল:** বর্ণিত হয়নি। ...
```
- **বাধ্যতামূলক ডেলিমিটার:** `### আয়াত N` বা `### আয়াত X–Y` (পার্সার রেঞ্জ-সচেতন)। বাংলা অঙ্ক ব্যবহার করো।
- `## ১২.`-এ বিদ্যমান টেবিল রেখে প্রতি আয়াত-গুচ্ছে বিক্বাঈ/রাযী/ইবনে আশূরের তানাসুব লাইন যোগ করো।

## ৪. বাস্তবায়ন ধাপ (৪ ব্যাচ)
1. **হারভেস্ট (রুকু ১–৩):** MCP থেকে asbab + তাখরীজ + বিক্বাঈ/রাযী/ইবনে আশূর নাযম → raw JSON (আংশিক)। বিক্বাঈ TOC → সূরার title_id/পৃষ্ঠা নির্ণয়।
2. **হারভেস্ট (রুকু ৪–৬):** বাকি আয়াত সম্পূর্ণ; দুই raw JSON-এ মোট আয়াত অক্ষত।
3. **MD রূপান্তর + enrichments:** রুকু MD-র `## ৬.` প্রতি-আয়াত ফরম্যাটে পুনর্লিখন (পুরোনো যাচাইকৃত তথ্য + কোয়ালিফায়ার সংরক্ষণ); `## ১২.`-এ নাযম লাইন; `ruku_XX_enrichments.json` তৈরি।
4. **UI/বিল্ড/প্রকাশ:** `MunasabatSection.jsx` + `tafsirTakhrijAdapter.js` নিশ্চিত; বিল্ড/যাচাই/প্রিভিউ; `git commit` + `git push` (push-এর আগে ইউজারের স্পষ্ট অনুমোদন)।

## ৫. যাচাইকরণ (অটোমেটেড)
```powershell
$env:PYTHONUTF8="1"; python scripts/build_web_data.py --surah <NNN>
$env:PYTHONUTF8="1"; python scripts/verify_web_data.py        # মোট আয়াত/রুকু পাস
node scripts/test_markdown_rendering.mjs                       # ০ ব্যর্থতা
npm run build --prefix web                                     # dist ত্রুটিহীন
```
- কাস্টম অডিট: দুই raw JSON-এ মোট আয়াত; enrichments-এ প্রতি আয়াতে `munasabat` + `nazm_scholars ≥ ২`; MD `## ৬.`-এ প্রতি আয়াত ডেলিমিটার, `> «...»`, `- **তাখরীজ:**`, `- **মুহাদ্দিসদের হুকুম:**` উপস্থিতি; শূন্য/জেনেরিক হাদীস আইটেম শূন্য।
- ম্যানুয়াল: প্রতিনিধিত্বশীল আয়াতে (স্বতন্ত্র নুযূল, নীতি-৩ আয়াত, রুকুর সমাপ্তি) কার্ড ভিউ + তাখরীজ সারণি + সনদ ব্যাজ + “শাস্ত্রীয় নাযম” প্যানেল যাচাই।

## ৬. রিস্ক/সতর্কতা
- মাক্কী সূরায় অধিকাংশ আয়াতে স্বতন্ত্র সববব নেই — নীতি ৩-এর ব্যাপক প্রয়োগ প্রত্যাশিত; ফাঁকা ঘটনা বানানো নিষিদ্ধ।
- বিক্বাঈ title_id অজানা হলে অনুমান নয়—TOC ব্রাউজ/সরাসরি turath থেকে নির্ণয়।
- পুরোনো অযাচাইকৃত দাবি রূপান্তরেও তার সতর্কতা-চিহ্নসহ থাকবে; নতুন যাচাই হলে কোয়ালিফায়ার আপডেট।
- `nazm_scholars` ঐচ্ছিক — অন্য সূরায় কোনো ব্যতিক্রম ছাড়াই রেন্ডার হবে।
- **Git push mutating — ইউজারের অনুমোদন ছাড়া নয়।**
