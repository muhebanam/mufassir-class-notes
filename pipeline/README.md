# জালালাইন তাহকীক পাইপলাইন (Python/API)

প্রতি আয়াতে আলাদা কাজ-ভাগ, স্কিল-নির্দেশনা (`skills/*/SKILL.md`), শেষে স্ক্রিপ্টে একত্রীকরণ ও অডিট। সূরা ১–১১৪ যেকোনো ক্রমে যোগ করা যায় — কোড কোনো সূরা-পরিসরে বাঁধা নয়।

## নকশা (এক নজরে)
```
harvest-plan → [আপনার MCP/IDE টুলে ক্যাপচার সংগ্রহ] → ingest (sha256 সিল)
   → plan → run (API, সমান্তরাল, রিজিউমযোগ্য)
         স্তর ১: আয়াত-ব্যাচ [অনুবাদ+জালালাইন | মুফরাদাত+ই'রাব | কিরাআত-মন্তব্য] ও তাফসীর-ইউনিট [তাফসীর+শানে নুযূল]
         স্তর ২: মাকাসিদ+সংযোগ | মতভেদ+আহকাম | উলূম+বালাগাত
         স্তর ৩: সমকালীন+দরস | সীমাবদ্ধতা
   → merge (LLM ছাড়া: আরবি আয়াত, কিরাআত-সারণি, গ্রন্থপঞ্জি স্ক্রিপ্টে) → audit → (approve)
```
**লেখক-এজেন্টের হাতে কোনো টুল নেই** — শুধু নিবন্ধিত উৎস। প্রতিটি আউটপুট `validate.py`-এর নির্ধারণবাদী যাচাই পার হলে তবেই সংরক্ষিত হয়; ব্যর্থ হলে ত্রুটি-তালিকাসহ এজেন্টকে ফেরত যায় (সর্বোচ্চ ৩ বার); টানা ৩টি টাস্ক ব্যর্থ হলে ব্যাচ থামে।

যা যাচাই হয়: প্রতিটি আরবি উদ্ধৃতি প্রদত্ত উৎসের (বা কুরআনের) হুবহু অংশ কি না; `[src:ID]` বৈধ কি না; সূত্র-সংখ্যা (হাদীস নং/খণ্ড/পৃষ্ঠা) উৎসে আছে কি না; কুরআন-রেফ (`﴿…﴾ ২৪:৩`) আয়াতের সাথে মেলে কি না; জালালাইন-রচয়িতা; কিরাআত-মন্তব্যে ক্বারী-নাম নেই; আয়াত Tanzil-এর সাথে হুবহু (স্ক্রিপ্ট-বসানো)।
**যা যাচাই হয় না:** ব্যাখ্যা বা তারজীহ শাস্ত্রীয়ভাবে সঠিক কি না, অনুবাদের মান, উৎসে থাকা কথার সঠিক সারসংক্ষেপ কি না — এগুলো মানবিক পর্যালোচনা।

## স্ট্যাটাস
| স্ট্যাটাস | অর্থ |
| :--- | :--- |
| `needs_work` | অডিটে ত্রুটি আছে বা অডিট চলেনি |
| `digital_verified` | সব যান্ত্রিক চেক পাস (উৎস-সাবস্ট্রিং, আয়াত-মিল, সারণি, আইডি…) |
| `gold` | শুধু `jp approve --by "নাম"`-এর পর, এবং ফাইল অপরিবর্তিত থাকলে (বদলালে আবার `digital_verified`) |

ফল লেখা হয় `00_প্রজেক্ট_তথ্য/audit_results.json`-এ (`{"rukus": {"46_1": {...}}}` — আপনার `build_web_data.py` v3.3 যে কাঠামো পড়ে)। বিদ্যমান এন্ট্রি মোছা হয় না।

## ইনস্টল
1. প্রজেক্ট-রুটে (যেখানে `00_প্রজেক্ট_তথ্য/` আছে) জিপ আনজিপ করুন → `pipeline/` ফোল্ডার তৈরি হবে।
2. `00_প্রজেক্ট_তথ্য/`-এ থাকতে হবে: `ruku_map.json`, `quran-uthmani.txt` (Tanzil, `সূরা|আয়াত|টেক্সট`)।
3. `pip install -r pipeline/requirements.txt` (শুধু আসল API-র জন্য)।
4. `pipeline/config.example.json` → `pipeline/config.json` কপি করে `llm.model` দিন (litellm মডেল-স্ট্রিং) অথবা পরিবেশ-চলক `JP_MODEL`। API-কী প্রোভাইডারের litellm-নিয়মে পরিবেশ-চলকে।
5. `python pipeline/jp.py validate-map` (মানচিত্র বনাম Tanzil)।

## এক রুকুর পূর্ণ প্রবাহ (উদাহরণ: সূরা ২৬, রুকু ১)
```
python pipeline/jp.py harvest-plan --surah 26 --ruku 1      # কী কী ক্যাপচার লাগবে
#   → IDE/MCP-তে docs/INBOX_FORMAT.md-র নিয়মে inbox/ ফোল্ডার ভরুন
python pipeline/jp.py ingest --surah 26 --ruku 1 --inbox inbox
python pipeline/jp.py run --surah 26 --ruku 1 --dry-run     # প্রম্পট দেখে নিন (API কল নেই): _work/s026/r01/prompts/
python pipeline/jp.py run --surah 26 --ruku 1               # এজেন্ট চালান (থামালে আবার চালালে রিজিউম)
python pipeline/jp.py merge --surah 26 --ruku 1
python pipeline/jp.py audit --surah 26 --ruku 1
python pipeline/jp.py approve --surah 26 --ruku 1 --by "মুফতী মুহাম্মাদ মুহিব্বুল্লাহ"   # পড়ে দেখার পর
python pipeline/jp.py status                                  # সব সূরার অগ্রগতি
```
সূরা বা পরিসর একসাথে: `go --surah 26 --to-surah 28` (ব্যর্থ/ব্লকড রুকু মার্জ হয় না, রিপোর্ট হয়)।

## ব্লকড টাস্ক = উৎস নেই
জালালাইন বা তাফসীর (role=tafsir) ক্যাপচার না থাকলে ওই টাস্ক `blocked` হয় — স্মৃতি থেকে লেখানো হয় না; নির্ভরশীল স্তরও ব্লকড, মার্জ হয় না। `_work/sNNN/rNN/tasks.json`-এ কারণ লেখা থাকে।

## নতুন সূরা (১–২৩ বা অন্য যেকোনোটি) যোগ করা
1. `ruku_map.json`-এ এন্ট্রি দিন (`dir_name`, `name_bn`, `name_ar`, `ayah_count`, `rukus: [[শুরু,শেষ],…]` — আপনার বিদ্যমান তিন ধরনের কাঠামোই চলে)।
2. `jp validate-map` — ধারাবাহিকতা ও Tanzil-এর আয়াত-সংখ্যা মেলে কি না দেখায় (রুকুর সীমানা নিজে মুদ্রিত মুসহাফ থেকে মেলান; টুল তা বলতে পারে না)।
3. ওপরের প্রবাহ। জালালাইন-রচয়িতা স্বয়ংক্রিয়: সূরা ১ ও ১৮–১১৪ → আল-মহাল্লী; ২–১৭ → আস-সুয়ূতী। সূরা ১ ও ৯ ছাড়া সব সূরার আয়াত ১ থেকে বিসমিল্লাহ ছাঁটা হয়।
4. সূরা-পরিচিতি (`00_সূরা-পরিচিতি.md`) এই সংস্করণে স্বয়ংক্রিয় নয় (পরের ধাপ)।

## খরচের হিসাব (আগে দেখে নিন)
রুকুপ্রতি কল ≈ অনুবাদ-ব্যাচ + মুফরাদাত-ব্যাচ + কিরাআত-ব্যাচ + তাফসীর-ইউনিট + ৫। ব্যাচিং `config.run`-এ (`batch_max_ayat`, `batch_max_words`, `unit_max_ayat`); ছোট আয়াত একসাথে যায়, আউটপুট কিন্তু আয়াত-ভিত্তিক। সূরা ২৬–১১৪-এ ৩,৩০৪ আয়াত — আয়াত-পিছু একটি করে সব স্কিল চালালে ১৩ হাজারের বেশি কল; ব্যাচিংয়ে অনেক কমে। `rpm`/`concurrency` আপনার কোটা অনুযায়ী ঠিক করুন।

## ওয়েব (build_web_data v3.3) এর সাথে
- `digital_verified` ওয়েবে এখন "Needs Work" ব্যাজ পাবে (শুধু `gold` ভিন্ন)। চাইলে ThematicView-তে `digital_verified`-এর জন্য আলাদা ব্যাজ-টেক্সট দিন।
- ফাইলে `[src:t7798-p123]` ট্যাগ থাকবে (অডিট এগুলোর ওপর নির্ভর করে); কিরাআত-সারণিতে নতুন প্রথম কলাম "ক্র." (Q1, Q2…)।
- `build_web_data.py` যেন `audit_results.json` না পেলে পুরনো হেডিং-গোনা `is_gold`-এ না ফেরে — ফেল-ক্লোজড (`needs_work`) করুন।
